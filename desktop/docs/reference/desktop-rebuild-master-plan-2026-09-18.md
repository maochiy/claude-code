# 自有 CLI 桌面端完整重做计划

日期：2026-09-18。状态：实施中；逐项实现和验收结果见 [实施状态](./desktop-rebuild-implementation-status.md)。本文是范围基线，不能据此推断任何阶段已经完成。

本文以用户最新澄清为准：**当前桌面项目提供架子，原 Proma 功能按官方 Claude Code 桌面交互与自有 CLI 的真实能力重做。** 旧代码是参考资产，不是已经验收的功能。此前文档中“保留应用编排/业务服务、只替换 Runtime Adapter”的实施策略由本文取代；此前源码事实和缺口记录仍可追溯。

## 1. 目标、范围与完成定义

- 主仓库：`/Volumes/code/code/agent/claude-code`。当前桌面整体迁入其 `desktop/`，迁移不遗漏属于产品的未提交和未跟踪源码。
- 复刻目标：官方桌面的布局、主题、交互、消息及执行显示。以用户截图、实际官方采样与可测试行为为依据，不照搬旧 Proma 语义。
- 执行内核：自有 CLI，移除 Pi 的正式执行路径；默认 Local，包含本机 worktree。模型可以使用已配置的本地或远端 Provider。
- 通信：独立本地服务管理独立 CLI 子进程，实时双向事件和控制；不是终端画面的包装器。
- 功能范围：本计划覆盖原桌面已有能力、用户提出的 UI 调整以及自有 CLI 的会话/模型/工具/权限/计划/任务/上下文能力。重做不等于静默删掉原能力。
- 可复用：经审查的 Electron 启动/窗口基础、基础 React 组件、样式素材、无业务语义工具函数和测试夹具。复用仍需重新验收。
- 重建：应用领域模型、会话状态机、执行服务、消息投影、交互结算、上下文与统计、任务调度、相关 IPC/Jotai 状态。旧类型和事件不能反过来限制新功能。
- 存储：JSON 配置与 JSONL 日志，不采用本地数据库；新旧数据有明确版本和导入边界。
- 不纳入首期：远端机器执行、云端会话服务、应用退出后的常驻 daemon。应用打开时的后台任务与定时任务属于首期完整范围。
- 完成：每项需求对应实现和验收证据，真实 CLI 与正式安装包通过；不能用“消息能返回”或“UI 已有组件”宣布完成。

## 2. 目标架构与数据所有权

```text
desktop/apps/electron
  Renderer：新的桌面交互 + Jotai 状态 + 消息/活动投影
        ↕ typed preload / Electron IPC
  Main：重做的桌面应用服务、配置/统计持久化、调度、系统能力
        ↕ loopback HTTP + 常驻双向 WebSocket
desktop/apps/local-service
  协议校验、会话进程、请求关联、事件序号、快照/重连
        ↕ stream-json/control（首选 stdio NDJSON）
现有 CLI：每个活跃会话一个独立进程
  模型循环、工具、六模式、计划、子代理、后台任务、原生历史
```

| 数据或能力 | 唯一职责方 | 约束 |
| --- | --- | --- |
| 模型循环、工具、原生审批策略、原生历史/检查点 | CLI | 桌面不执行第二套 Agent 循环，不修改原生 transcript 来伪造恢复 |
| CLI 进程、控制请求、事件顺序、重放缓存 | Local Service | 一会话一进程，版本和能力握手；不另外建业务数据库或第二套定时调度 |
| 桌面项目/会话索引、显示投影、用量记录、应用调度 | 重做的 Main 应用服务 | 明确单一写入方与数据版本；可从日志重建投影 |
| 凭据、PTY、窗口、浏览器、麦克风和系统通知 | Main 的受控能力服务 | 凭据不发到 Renderer，不进入模型正文或诊断日志 |
| 面板开关、高度、展开、导航、滚动 | Renderer/Jotai | 关闭面板不决定 CLI/PTY/后台任务生命周期 |

新增纯 TypeScript `desktop-protocol` 包；桌面应用事件不直接等同 CLI 内部类型，通过单一映射层转换。CLI 不产生 `_proma*` 专属字段。原有会话辅助 CLI 的搜索/导出能力纳入重做，避免与执行 CLI 混淆。

## 3. 阶段 0：建立需求与官方行为基线

产出需求编号、官方参考截图/操作记录、事件夹具、模块归属和验收表。状态统一使用“未实现/实现中/离线通过/真实 CLI 通过/视觉通过/安装包通过”，不再把源码存在标成完成。

1. 整合现有截图与采样：用户消息、过程/最终正文、工具多层展开、模式、Plan、任务标签和右侧堆叠。
2. 补真实样本：thinking 各阶段、AskUser 单/多问题、ExitPlan 批准/反馈/拒绝、压缩过程与上下文详情、worktree 生命周期。
3. Auto/dontAsk 按自有 CLI 能力制定交互；官方采样未出现不代表可以不接。
4. 所有写文件/执行/回退测试只用隔离 fixture 项目，不用正在工作的业务项目。
5. 品牌名尚未指定，不阻塞协议与功能；在发布前统一品牌、appId、更新源和数据迁移方案。

验收：每个明确用户需求都有条目，样本缺失明确标记，不靠模型模拟文字冒充真实交互。

## 4. 阶段 1：同仓迁移与独立构建

1. 重新记录两仓 HEAD、工作树、未跟踪源码清单；创建迁移分支和可核对 manifest。不删除原桌面目录。
2. 将 apps、packages、资源、测试、必要文档迁入 desktop/；不搬 .git、依赖目录、构建缓存、真实配置或用户会话。
3. CLI 根工程与 desktop 保留独立依赖和锁文件，避免 React/TS/Vite 与测试环境冲突；根级命令分别调用两个工程，不把 desktop 包强行合入根 workspace。
4. CLI、Local Service、Electron 使用独立构建/测试入口和输出目录，避免根测试 preload、清理脚本相互影响。
5. 建立新模块骨架和旧功能迁移台账；旧业务代码可暂留作参考，但不作为新功能完成依据。

验收：干净环境能分别构建 CLI 和桌面，现有 CLI 行为不因合仓回归；资源路径和当前源码迁移完整。

## 5. 阶段 2：本地服务与实时协议

1. Main 启停服务，服务启动/能力握手、回环绑定、认证、协议版本与构建 ID。
2. 每会话 CLI spawn/cwd/env/resume；区分执行中、待审批、有后台任务、空闲、崩溃和已退出。不得回收仍有任务的进程。
3. NDJSON 半包、Unicode、大输出、背压、stderr 分离；持续流不能整轮缓冲后才显示。
4. 请求关联 requestId；事件包含 sessionId、runId、进程代次、sequence、message/tool/task ID。控制确认和执行终态分别处理。
5. snapshot + 增量重放、去重、断线恢复；不能因为重连再次执行用户发送、审批或工具。
6. send/queue/cancelQueued/interrupt、配置控制、审批答复、任务输出/停止、上下文查询和压缩形成明确接口。
7. UI 重载/关闭面板不停止执行；应用退出有序处理子进程树和未结算交互。

验收：fake CLI 跨进程测试覆盖流式、控制、崩溃和重连，再用隔离项目验证真实 CLI 往返。

## 6. 阶段 3：补齐 CLI 能力与模式控制

### 六种模式

| 模式 | 必须实现的语义 |
| --- | --- |
| default / Manual | 按原生权限规则，请求人类审批 |
| acceptEdits | 原生允许编辑的策略，其他工具按规则处理 |
| bypassPermissions | 明确绕过模式，不能被用作 Auto 或错误的默认回退 |
| plan | 原生计划限制、进入/退出、文档、批准后的目标模式 |
| dontAsk | 不询问时按策略允许或拒绝，不等于全部允许 |
| auto | 真正分类器判断、检查中/结果/不可用状态，必要时仍询问用户 |

所有切换都通过 CLI 确认及状态回报生效；失败保留有效状态。清除旧 auto→bypass 的迁移语义。

### 已查明的内核工作

- 统一 Auto 启动与动态切换门禁，补 classifier 状态和可归属 usage；不靠硬编码支持标记。
- 修复 effort 清空与实际设置不一致；区分 effort 与 thinking budget。模型、渠道、凭据变更按能力热更新或受控重建并恢复。
- 补任务日志游标/订阅、单任务停止结果、任务快照、子代理关系/执行图/transcript 的真实出口。
- 完善 get_context_usage schema 中已返回的字段；真实阈值与执行共用计算；按产品明细需求开放受限制的逐项数据。
- 补会话级自动压缩开关及有效状态；补 compact post_tokens 等 schema 和必要终态。
- 清空/对话回退可先通过受控重启 + 原生恢复参数实现；文件回退独立确认，不能把 rewind_files 当对话回退。
- 命令目录携带能力分类：headless 命令、桌面动作、Skill、仅终端命令；需要的终端专用功能提供真实桌面实现。
- 核对所有现有 Provider 协议、MCP/Hooks/配置作用域和多模态；不根据模型名或 URL 猜测 API 协议。

验收：六模式覆盖读、写、Bash、MCP、询问、计划和拒绝；必要能力缺失必须实现，不能隐藏入口或返回空结果交付。

## 7. 阶段 4：重做会话、消息和执行展示

### 会话及运行状态

- 新建、历史、搜索、重命名、置顶/归档/删除、会话分叉、恢复、回退；桌面 ID 与原生 ID 分开。
- 多会话并发隔离；后台执行/待审批提示；输入队列、停止、失败后继续与迟到响应。
- 清空会话、压缩和删除互不混淆；显示历史不等于恢复原生执行上下文。

### 展示时间线

- 用户消息、图片/文档附件、长文展开和操作；过程正文、thinking、工具、最终正文按实际顺序呈现。
- 等待时长、模型状态、Token、执行中/完成/停止/失败；无 thinking 数据时只显示真实状态。
- 流式增量、完整快照和 result 对账，避免重复正文；跨重载仍保持消息顺序。
- Read/Bash/Edit/Search 等聚合、单次工具与结果展开；输入/输出/错误/拒绝/取消、diff、Copy、长输出滚动与实时输出入口。
- Thinking 的折叠/高度/结束后行为按官方真实样本定稿，不继续沿用互相冲突的旧组件规则。
- Copy/Fork/Pin/Rewind 等操作按消息角色和参考行为实现；自动滚动、手动离底暂停、回到最新、展开状态持久保持。
- 消息内本地文件、改动、计划、任务入口打开对应面板。

验收：正文与工具交错、并行工具、失败/中断、连续追问、长输出和历史回放都准确；同序列官方截图与桌面截图逐项对照。

## 8. 阶段 5：重做审批、计划、后台任务和子代理

- Permission、AskUser、ExitPlan 是三类独立请求。支持允许一次/按规则允许/拒绝，结构化单选、多选、自由回答，多问题、反馈和取消，以 CLI 实际输入结构为准。
- 输入框上方交互、待处理队列、切会话/重载恢复、已结算回应和迟到回应去重；拒绝工具后按原生语义继续。
- Plan 文档与审批状态分离；生成可用计划自动开面板、内容可点击打开、完整 Markdown、更新版本、批准/反馈/拒绝及批准后的目标模式。
- Todo/任务清单不冒充可批准的计划文档；计划评论和工具栏按参考补齐。
- 后台 Shell 与原生子代理：started/progress/completed/failed/stopped，运行与已完成列表、真实输出、单停、清理已完成、父子关系与可用 transcript。
- 蓝色任务标签点击打开面板；前台 result 不结束后台任务。任务面板、终端 PTY、应用定时任务分开建模。
- Plan/任务入口仅在当前会话具备内容时显示；两面板可上下同时展示，关闭一块后另一块自动填满。

验收：反馈后重新提出计划、批准后模式正确；两个后台任务只停一个；前台结束后任务继续、重载恢复，所有审批恰好结算一次。

## 9. 阶段 6：重做上下文、压缩和统计

### 上下文

- 接 get_context_usage，展示 Messages/System prompt/System tools/MCP/Memory/Skills/其他实际分类、容量、已用/剩余、缓存等明细。
- 真实 usage 与估算分类分别标记，缺失与零值区分；模型切换允许窗口变小，不能永久取历史最大值。
- 打开弹层、轮次结束、模型/MCP/Skills/压缩变更时合并刷新；分析可能触发 token-count API，不做逐 token 高频查询。

### 压缩与上下文操作

- `/compact [instruction]` 由 CLI 原生命令处理；自动启用/阈值按原生实际策略，提供运行中修改和确认。
- manual/auto、开始、成功、noop、失败、停止、压缩前后值和摘要；历史边界、压缩后继续、重启恢复。
- 成功后占用下降、后续实际 usage 替换估算；压缩不降低累计历史用量。
- clear/rewind/fork 同步上下文、原生会话映射及交互状态，不能只删界面内容。

### 统计

- 重做 usage 日志与聚合：用户消息数、轮次、模型调用数分别定义；Code/Cowork/Chat 来源明确。
- 日/周/月范围、热力图、模型排行、会话与活跃统计、图表/表格、鼠标悬浮、键盘访问和实时刷新。
- result.usage 与累计 modelUsage/cost 分别归一化；按 session/进程代次/恢复基线去重并取差额。
- 主执行、Auto 分类器、子代理、压缩和重试开销有归属；父子汇总不重复计入。输入/缓存是否包含由协议语义确定。
- 服务商额度独立取真实接口数据；不从本地 Token 消耗推测剩余额度，不填假零。

验收：两轮及多模型统计精确增量；重放不翻倍；压缩前后占用正确；时间范围和图表一致；未计入或读取失败可见。

## 10. 阶段 7：重做项目、Git、worktree 和独立面板

- 新会话项目/分支选择可操作；worktree 是勾选状态，选择本身不执行任务。
- 新会话勾选和分支选择先保存为草稿，首次发送时准备实际 worktree；目录未就绪时不执行、不打开错误目录的终端。失败保留草稿与可重试状态，不回退到用户 Home。该流程须结合补充的官方样本验收。
- worktree 创建、打开、恢复、分叉、退出及清理边界明确；保留用户修改，Git 操作有实际结果和错误反馈。
- dirty worktree 清理失败必须保留目录并显示原因，不能只删除桌面记录或只写日志。
- 会话执行、终端、文件树、Diff 都绑定同一个真实 cwd，不能出现面板看主目录、CLI 改 worktree。
- 文件浏览/搜索/打开、改动汇总与逐文件展开、代码预览、路径点击、工具修改后的刷新。
- Git 坞统计点击打开右侧改动；“创建 PR/提交变更”下拉只更换选择，再点主按钮才执行。
- 终端按会话保留 PTY 和滚动内容，支持多个终端实例；面板 X 隐藏不重置，关闭具体实例另行结束该 PTY。
- 文件、终端、改动、Plan、后台任务是独立面板类型；不合成终端/文件混合 tab。终端内部多实例 tab 仍支持。
- 右侧悬浮留白、圆角、阴影、拖动宽度与全屏/展开；Plan/任务支持上下布局。切会话默认收起右侧面板，不停执行。

验收：隔离仓库真实分支/worktree 操作及编辑回退；PTY 隐藏重开内容仍在；会话目录不串；面板关闭与尺寸行为和截图一致。

## 11. 阶段 8：重做命令、配置、应用任务与其他入口

### 输入及能力目录

- `/` 同时显示原生命令与 Skills，支持过滤、键盘选择、参数提示、作用域和动态更新。
- 选择与发送分离；本地动作、原生命令和模型任务分别路由。不把终端专用命令直接当提示词发送。
- MCP 连接/状态/配置与工具权限，用户/项目设置、指令文件、Hooks、Skills 和 CLI 支持的扩展能力统一按原生作用域加载。
- 图片/文档/拖拽/粘贴、附件授权，排队、重载、分叉后的附件可读性。

### 模型与设置

- 渠道/模型/API 模式、凭据、能力、effort、thinking、上下文和输出配置；启动/动态更新/恢复一致。
- 设置删除隐私、协作、导入导出、插件页面入口；连接器改为“模型配置”，用户菜单“推理配置”改为“模型配置”，去掉“查看更多”。
- 删除页面入口不等于删除已要求接入的内核扩展能力或内部数据迁移能力。
- 重新接通真实行为：消息宽度、完成通知、动态工作流、提醒、保持唤醒、输出样式、本地 sandbox 与严格策略。保留的开关必须有消费者和可测效果；语义不适用者明确处理，不能保留假开关。

### 应用能力

- 任务面板/看板、定时任务重做，任务与会话关联和导航；创建、编辑、运行、暂停、删除、结果/失败、权限等待、应用重启。
- CLI 会话内 cron 与应用定时任务标明来源和生命周期，不重复调度；无人值守运行遵守所选权限策略。
- 应用协作与原生子代理关系统一，委派/继续/取消/结果有明确身份；不复用旧的清空 runtimeSessionId 后盲目重放逻辑。
- 原有普通 Chat/多 Provider 能力和外部入口逐项重建映射：飞书/钉钉/微信等已有集成、快捷任务、浏览器、语音、系统通知等；共享新会话/权限/附件/运行服务，不各自启动另一条执行链。
- 自动更新、代理配置、运行环境检测、多工作区、会话辅助 CLI 的 list/info/outline/search/export 同样进入迁移台账；按新的应用结构重接并测试，不因未出现在主对话界面而遗漏。
- 外部服务先用本地 mock/测试入口验收；真实发送另按用户授权和测试账号范围验证，不向真实联系人试发。

验收：每个原有功能有新的实现映射或用户明确取消记录；不存在主窗口用新 CLI、其他入口残留 Pi 的情况。

## 12. 阶段 9：全局视觉与交互一致性

## 14. 实施依赖、分工与测试门槛

关键路径：行为基线 → 同仓构建 → 协议与服务 → CLI 补齐 → 新会话/投影 → 全功能贯通 → 视觉/数据/安装包。

协议冻结后可分工：CLI 控制能力、本地服务、桌面状态/展示、项目面板、统计上下文、应用任务/入口各有独立所有权。主代理负责接口合并和端到端验收；避免多个 Agent 同改大编排文件。

每阶段交付：实现文件、协议/数据变更、BDD 场景、运行证据、尚未通过条目。没有做的检查明确记为未验证。

必须覆盖的测试层次：

1. 纯逻辑：增量/累计、消息投影、任务和交互状态机、上下文阈值、存储恢复。
2. 跨进程：Main/Service/fake CLI，半包/乱序/重复/断线/崩溃/迟到控制。
3. 真实 CLI：隔离仓库验证六模式、工具、计划、询问、后台、worktree、压缩、分叉/回退、多模型和多会话。
4. 视觉交互：官方样本对照，主题/语言、流式滚动、面板、菜单、真鼠标与键盘。
5. 安装包：资源和版本、启动/升级/恢复、无开发依赖、退出清理。

实时性记录四段：CLI 事件→服务、服务→Main、Main→UI 首帧、控制请求→实际确认；测首事件、大输出、多会话和后台日志。记录分布后设性能门槛，不凭空承诺毫秒数。

不预估缺少实测依据的工期；以阶段门槛推进。所有阶段都在正式范围内，阶段划分不是缩减为首版功能。
